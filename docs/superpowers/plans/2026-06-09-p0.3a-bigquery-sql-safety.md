# P0.3a — BigQuery PB tail + text-to-SQL safety (cost guard + AST gate)

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development or superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Make the BigQuery PB-tail queryable safely: a `GuardedBigQuery` client wrapper enforcing the S4 four-gate contract (read-only `sqlglot` AST gate · mandatory partition filter · `maximum_bytes_billed` dry-run cap · BigQuery transpile), config-driven (CONFIGURABLE), with a creds-gated live path. The BigQuery public datasets (NYC TLC, GDELT, TPC-DS) are already catalog assets (query-in-place, PB tail) carrying `SecurityContext` + masked PII columns — P0.3a adds the executable safe-query layer + a `BigQueryConnector` that registers/queries them.

**Architecture:** `sql/ast_gate.py` (read-only AST validation via sqlglot) + `sql/cost_guard.py` (partition-filter + byte-cap checks) + `connectors/bigquery.py` (`GuardedBigQuery` wrapper around a BigQuery client behind a `BigQueryClient` Protocol — a `FakeBigQueryClient` for local tests, the real `google-cloud-bigquery` client for the creds-gated live path). Config carries `bq_max_bytes_billed`, `bq_require_partition_filter` (CONFIGURABLE — no magic numbers). Governance is unchanged: warehouse assets already carry `SecurityContext`; column masking for `customer_email`/coords is declared in the estate (world-bible §6) and enforced by the existing C1 masking — P0.3a confirms masked columns never appear in a result the role can't see (a governance test over the warehouse asset).

**Tech Stack:** `sqlglot` (AST + transpile), `google-cloud-bigquery` (optional extra, live path only), the existing catalog/governance, the S4 contract (`docs/spikes/s4-bigquery-cost-guard.md`).

## External-service ground rules
