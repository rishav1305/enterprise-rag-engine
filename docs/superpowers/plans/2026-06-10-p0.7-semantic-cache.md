## Headline governance invariant (the P0.7 leak oracle — FAIL-CLOSED)
**A cached answer/result must NEVER be served across a permission boundary.** A cache keyed only on query-embedding similarity would serve User A's cached answer (content A is cleared for) to User B who is NOT — a cache-mediated permission bypass.

Two defenses, both implemented (defense in depth):
1. **Scoped key** — the cache key incorporates the session's *authorization scope* (`clearance_level` + sorted `roles` + sorted need-to-know), not just the query. A different scope → different key → cannot hit another scope's entry.
2. **Re-govern on hit** — the cache stores the *governed* payload (the `authorized_chunk_ids` + the per-chunk governance trail), and on a hit the governance decision is RE-APPLIED for the requesting session before anything is returned. Even a key collision cannot leak: the stored content is re-filtered.

**Headline hardened test:** high-clearance session populates the cache; a low-clearance session issues a *semantically identical* query → CACHE MISS (different scope key) — and if we force a key hit, the re-govern path redacts/denies — NEVER the high-clearance answer.
**Mutation (the bite):** drop the scope component from the key → the low-clearance query hits the high-clearance entry → cross-clearance leak → headline test FAILS. (Friday will also mutate this independently.)

## Architecture
Standalone subsystem under `src/rag_engine/cache/` (built + hardened this phase; pipeline wiring is a tracked seam, like TurboVecRetriever/text-to-SQL/Tracer were built-then-wired). Reuses the existing `HashingEmbedder` (deterministic, no creds) for semantic match; `Tracer`/`FunnelTrace`/`AuditSink` for the TRANSPARENT cache-hit trail.

## Spine (serial, single-writer) — Tasks 0–2
- **T0 — cache key + scope (`cache/key.py`).** `AuthScope.from_session(session)` → frozen, hashable `(clearance_level, tuple(sorted(roles)), tuple(sorted(ntk)))`. `scope_fingerprint()` → stable sha256 hex. This is the permission boundary in the key. SPINE.
- **T1 — `SemanticCache` (`cache/semantic_cache.py`).** The engine. `CacheEntry` (query_text, query_vec, scope_fp, governed payload = authorized_chunk_ids + trail + answer, ts, ttl). `get(query, session, govern_fn)`: embed query → among entries with the SAME scope_fp, find max cosine ≥ threshold → on hit, RE-APPLY `govern_fn` for this session over the stored chunk ids, return the re-governed result + a `CacheHit` record (similarity, span/funnel/audit hooks fire); else MISS. `put(query, session, governed_payload)`. TTL + max-size LRU eviction (ELASTIC bounded footprint). SPINE.
- **T2 — config knobs (`config.py`).** `cache_enabled`, `cache_similarity_threshold` (cosine), `cache_ttl_seconds`, `cache_max_entries`, `cache_backend` (memory|surreal). All env-overridable, schema-validated, CONFIGURABLE (no magic numbers). SPINE.
