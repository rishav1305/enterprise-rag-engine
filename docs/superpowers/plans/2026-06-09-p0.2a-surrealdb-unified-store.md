# P0.2a — SurrealDB Unified Store Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Replace the in-memory catalog/store with a SurrealDB-backed implementation behind the **same `Connector`/`CatalogRegistry` surface**, modeling catalog + ACLs + the four retrieval modes (graph, SurrealQL/structured, full-text, vectors-by-id) in one engine — with **both** a local self-host profile (CI/dev) **and** a SurrealDB Cloud profile real and tested, and the 210-cell oracle + leak demo + C1 masking enforcement staying green through the swap (regression parity).

**Architecture:** A `SurrealStore` wraps a SurrealDB connection (DSN from config). A `SurrealConnector(Connector)` discovers `CatalogAsset`s from SurrealDB rows instead of the seed estate; `CatalogRegistry` is unchanged (it consumes any `Connector`). The P0.1a `emit` gains a SurrealDB target so the estate loads into the DB. Retrieval-mode methods (graph traverse, SurrealQL aggregate, full-text search, vector-id fetch) live on `SurrealStore`. TurboVec keeps the vector ANN (per S2); SurrealDB holds vectors-by-id + metadata. Connection is config: `surrealdb-local` (in-memory CI / surrealkv dev) and `surrealdb-cloud`, same DDL.

**Tech Stack:** SurrealDB 3.1.x (`surreal` CLI for local), `surrealdb==2.0.0` Python SDK, 3.x DDL (HNSW vector index, FULLTEXT search, `REMOVE … IF EXISTS`), the existing `catalog/` + `governance/` from P0.1b, the P0.1a `seeds/` estate.

> **S2 spike (done, `docs/spikes/s2-surrealdb-four-mode.md`):** one instance serves all four modes; vector ANN stays in TurboVec; local self-host tested independent of titan-pc. DDL syntax pinned there.

## Multi-setup requirement (robust directive — both real + tested)
- **`surrealdb-local`** — `surreal start memory` (CI, deterministic) and `surrealkv://` file (durable dev). No titan-pc dependency.
- **`surrealdb-cloud`** — SurrealDB Cloud free tier (account exists). Same DDL, env-driven DSN.
- A test matrix runs the store contract against the **local** profile in CI; the cloud profile is covered by a `-m cloud` marked test (skipped without creds) so the path is real but doesn't gate CI on a network service.

## Regression-parity gate (the key gate)
The 210-cell oracle, the INTERN-vs-CFO leak demo, and the C1 end-to-end mask test MUST stay green when the catalog source is swapped from `SeedConnector` to `SurrealConnector`. A parametrized parity test runs the oracle against BOTH connectors and asserts identical decisions.

VECTOR_DIM = 1024  # Voyage-3-large (matches the TurboVec index)


def ddl_statements(vector_dim: int = VECTOR_DIM) -> list[str]:

```python
# src/rag_engine/store/surreal.py
from __future__ import annotations
from typing import Any
from .schema import ddl_statements


class SurrealStore:
    def __init__(self, dsn: str, ns: str, db: str, user: str, password: str) -> None:
        self.dsn, self.ns, self.db, self.user, self.password = dsn, ns, db, user, password
        self._db = None

    def connect(self) -> None:
        from surrealdb import Surreal
        self._db = Surreal(self.dsn)
        self._db.signin({"username": self.user, "password": self.password})
        self._db.use(self.ns, self.db)

    def apply_schema(self, vector_dim: int = 1024) -> None:
        for stmt in ddl_statements(vector_dim):
            self._db.query(stmt)

    def upsert_asset(self, asset: dict[str, Any]) -> None:
        self._db.query(
            "UPSERT type::thing('asset', $id) CONTENT $data;",
            {"id": asset["asset_id"], "data": asset},
        )

    def get_asset(self, asset_id: str) -> dict[str, Any] | None:
        r = self._db.query("SELECT * FROM type::thing('asset', $id);", {"id": asset_id})
        return r[0][0] if r and r[0] else None

    def close(self) -> None:
        if self._db is not None:
            self._db.close()
```

from __future__ import annotations
import sys
from pathlib import Path
sys.path.insert(0, str(Path(__file__).resolve().parents[2]))
from seeds.emit import build_estate  # noqa: E402


def load_estate(store, scale: float = 1.0) -> int:
    manifest, _ = build_estate(scale=scale)
    n = 0
    for a in manifest.assets:
        store.upsert_asset({
            "asset_id": a.asset_id, "cls": a.sensitivity_class, "level": a.clearance_level,
            "vertical": a.vertical, "retrieval_mode": a.retrieval_mode,
            "owner_department": a.owner_department,
            "columns": [{"name": f.name, "pii": f.pii, "masked": f.masked} for f in a.fields],
        })
        n += 1
    return n
