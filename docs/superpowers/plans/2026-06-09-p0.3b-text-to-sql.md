# P0.3b — Text-to-SQL agent + adaptive routing (governed, can't-leak)

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development or superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** An NL→SQL agent that can ONLY emit guarded read-only SQL (through the P0.3a `GuardedBigQuery`), whose **result rows pass through the masking path before reaching the model** (the headline: text-to-SQL that can't leak), plus an adaptive router (semantic-router, local encoder) that picks the retrieval mode (vector / warehouse-SQL / graph / lexical) with the regex `HeuristicRouter` as the deterministic fast-path/fallback.

**Architecture:**
- `texttosql/agent.py` — `TextToSqlAgent(generator, guarded_bq, asset)`: NL question → the `Generator` ABC drafts SQL (Groq/NVIDIA live; a **deterministic `FakeSqlGenerator`** for tests) → `GuardedBigQuery.run()` (P0.3a gates: read-only AST + cost guard) → **result rows masked** per the asset's column policy before they become model context → the existing extractive/LLM generator answers from the **masked** rows.
- `texttosql/result_masking.py` — `mask_rows(rows, columns, decision)`: applies `redact_chunk`-equivalent masking to columnar SQL results (a class-D/masked column → `[REDACTED]`/`[RESTRICTED]` per `mask_reason`), governed by the session's decision over the warehouse asset. **This is the 🔴 HARD GATE.**
- `routing/semantic_router.py` — `SemanticRouter(QueryRouter)` over semantic-router with a **deterministic local encoder** (Tfidf/our HashingEmbedder — no LLM, no creds in the hot path); routes vector vs warehouse-SQL vs graph vs lexical. `HeuristicRouter` stays the fast-path; `SemanticRouter` is opt-in via config (multi-setup: both real).

**🔴 HARD GATE CONDITION (carried from P0.3a governance review):** warehouse SQL RESULT ROWS must pass through masking before reaching the model. A masked column (`customer_email`, NYC TLC coords) in a SELECT result is `[REDACTED]` in answer + citations, never raw — AND never reaches the generator's input. E2E test (hardened: assert the masked value is absent from the generator input, not just the output) + an under-cleared-persona governance proof.

**Tech Stack:** P0.3a `GuardedBigQuery` + `sql/` gates; the `Generator`/`QueryRouter` ABCs; `governance/masking` (`redact_chunk`/`mask_value`); `semantic-router` (local encoder); deterministic fakes for no-creds tests.
