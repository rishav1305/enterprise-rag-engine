## P0.11a — INTEGRATION WIRING (FIRST; highest governance risk) · branch `feat/p0.11a-integration`
Wire every built-standalone component into the live `RAGPipeline.query`, each carrying
the governance invariant the reviewers flagged, AND a pipeline-level integration test
through the REAL `SecurityFilter`/governance. **Master headline: the leak oracle must
pass END-TO-END through the fully-wired pipeline** — a standalone-safe component can
leak once wired, so this is the master gate.

Today `RAGPipeline.query` = route → retrieve → L5 `SecurityFilter.apply` → audit →
citations → generate. The cache / loop / tracer / text-to-SQL / mode-retrievers / CDC /
multimodal-extract are all standalone. Wire them as OPTIONAL injected collaborators
(default off → existing tests + the 210-cell oracle stay green), each gated on its
config flag, each with the real governance on the path.

### Increment order (each: failing pipeline-integration test → wire → mutation-prove → commit)
- **W1 — Tracer + Langfuse attribute allowlist.** Spans around route/retrieve/govern/
  generate in `query`; a Langfuse exporter that only emits a METRIC-KEY allowlist
  (request_id/cost/tokens/mode/n_admitted/decision-counts) so `span("generate",
  answer=...)` can't leak content. Test: a seeded PII sentinel in a chunk never appears
  in any exported span attribute. Mutation: drop the allowlist → content leaks → fails.
- **W2 — SemanticCache wired with the REAL govern_fn.** At `query` entry (cfg.cache_enabled):
  `cache.get(question, session, govern_fn)` where `govern_fn` re-runs `SecurityFilter`
  over stored chunk ids for the session (NOT identity); miss → run pipeline → `cache.put`;
  emit `record_cache_hit`. Test: under-cleared session never gets a high-clearance cached
  answer; partial-redaction → miss (recompute). Mutation: identity govern_fn → cross-
  clearance cache leak → fails.
- **W3 — CorrectiveLoop wired with the REAL session-scoped retrieve_fn.** (cfg.selfrag_enabled):
  loop's `retrieve_fn` = the pipeline's session-scoped retrieve (vector/mode); the loop
  self-redacts (belt-and-suspenders). Test: a corrective re-retrieval never surfaces a
  denied/mask-raw chunk end-to-end. Mutation: pass a permission-blind retrieve_fn → leak.
- **W4 — mode-router + ReBAC AllowlistBackend.** Route graph/structured/lexical queries
  to the P0.6 mode retrievers (session-scoped) selectable via cfg; allowlist backend from
  cfg (in-process default | ReBAC). Test: a denied chunk never surfaces in the routed
  non-vector mode end-to-end; the wired backend agrees with the in-process decision.
- **W5 — text-to-SQL + GuardedBigQuery.** Route warehouse-SQL queries through the agent;
  result rows masked through the REAL governance (mask flag from the GovernanceDecision
  over the warehouse asset, ColumnPolicy from the catalog — not literals). Test: a
  warehouse result row's restricted column is masked end-to-end. (BigQuery client = the
  Fake; live gated.)
- **W6 — multimodal `guarded_extract` into ingest.** `index_documents` routes non-text
  sources through `guarded_extract(<extractor>, doc, raw)` so produced chunks inherit the
  doc's SecurityContext; a masked image is withheld end-to-end via the same L5 path.
- **W7 — CDC processor + embedder_version in the query path.** `RAGPipeline` exposes an
  `apply_change(event)` that drives `CdcProcessor` (store+cache); queries select the
  matching `embedder_version`. Test: a reclassify-up via the pipeline → the under-cleared
  session's next query is denied + cache invalidated end-to-end.
- **W8 — MASTER END-TO-END LEAK ORACLE.** Drive the FULLY-WIRED `RAGPipeline.query`
  (every component on) for a spread of personas × classes and assert: a denied chunk's
  content NEVER appears in the answer/citations; a masked chunk is `[REDACTED]`/withheld;
  no raw multimodal payload in the response; matches the 210-cell ground-truth decisions.
  Mutation: any single wired component bypassing governance → a cell leaks → fails.
