# P0.6 — Governance pre-filter for ALL retrieval modes + sub-linear ReBAC allowlist

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development or superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal (most governance-critical phase since P0.1b):** extend the index-level permission **pre-filter** — today only the vector mode (TurboVec allowlist) — to **graph / structured-SQL / lexical** modes (a denied node/row/hit is never returned, *before* the L5 post-filter), and replace the O(N)-per-query allowlist scan with a **sub-linear ReBAC backend** (Oso Cloud + SpiceDB, both real) behind an ABC — **with a parity guarantee that the ReBAC backend returns EXACTLY the same allow/deny set as `access.evaluate`** (a diverging backend is a leak or over-deny).

**Architecture:**
- **Allowlist ABC** (`governance/allowlist.py` extended): `AllowlistBackend` protocol — `authorized_ids(session, candidates) -> set[str]`. Implementations: `InProcessAllowlist` (the existing `access.evaluate` scan, the DEFAULT + zero-dep fallback), `SpiceDBAllowlist` (self-host, binary/creds-gated), `OsoCloudAllowlist` (hosted, creds-gated). **Parity test**: every backend == `InProcessAllowlist` on the 210-cell-equivalent matrix (a diverging backend fails CI).
- **Per-mode pre-filter** (`store/surreal.py` retrieve methods + `retrieval/` mode wrappers): each mode constrains its SurrealQL by the session's allowlist so denied content is never a candidate:
  - **Graph** — traversal `WHERE id IN $allow` (a denied node is never traversed-to / returned).
  - **Structured/SQL** (SurrealQL) — `SELECT … WHERE asset_id IN $allow_assets` (denied-asset rows never returned); the P0.3b text-to-SQL result-masking stays (defense in depth).
  - **Lexical/full-text** (BM25 `@@`) — `… @@ $q AND id IN $allow` (full-text hits on denied content excluded).
- For **each** mode: a **hardened** test — a denied node/row/hit is NEVER in the mode's candidate set for an under-cleared session, asserted on the **retriever output BEFORE the L5 post-filter** (so it fails if that mode's pre-filter is bypassed — the P0.2c/P0.3b pattern). 210-cell oracle + leak demos stay green.

## External-service / binary ground rules
- Pre-filter-all-modes CORE is fully LOCAL/no-creds (SurrealDB `surreal_local` fixture; `InProcessAllowlist` default). 
- **SpiceDB**: a local `spicedb serve` (binary-gated, like `surreal`); `@pytest.mark.spicedb` skipif no binary. **Oso Cloud**: `@pytest.mark.oso` skipif no `OSO_AUTH` env. The `InProcessAllowlist` default is ALWAYS tested. The **parity test runs against whatever ReBAC backend is available** (in-process always; SpiceDB/Oso when present) — so parity is enforced for the default no matter what, and for the ReBAC backends on demand.
- **CORE = the 3 new pre-filters + the in-process allowlist parity** — fully provable no-creds. ReBAC backends are the *optimization*, gated. NOT a blocker.
