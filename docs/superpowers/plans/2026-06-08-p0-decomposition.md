## Tracked follow-ons (not yet built — explicit so they aren't lost)
- **Recall on REAL Voyage embeddings (not the CI HashingEmbedder):** P0.2b re-validated recall on clustered + HashingEmbedder vectors (honest ~0.45 tight / ~0.90+ text; reranker recovers). The production embedder is Voyage-3-large — recall on *real Voyage* embeddings is a **creds-gated** validation to run when a Voyage key is available (the offline build path). Until then the reranker-load-bearing finding stands. → fold into P0.2b-followup / the offline-build phase.
- **Adaptive router:** still the regex `HeuristicRouter`. **semantic-router** (spec §9, MIT, local, embedding-similarity) replaces it on the vector path. → P0.3b ("router learns indexable-derivative vs PB-tail") is the natural home; adopt semantic-router there.
- **ReBAC sub-linear allowlist:** ✅ DONE (P0.6) — `AllowlistBackend` ABC; `InProcessAllowlist` default + `LocalReBACAllowlist` (zero-dep tuple kernel) + `SpiceDBAllowlist` (authzed, gated) + `OsoCloudAllowlist` (gated); list-objects sub-linear lookup, **parity-guarded** against the in-process decision so the optimization never changes allow/deny. (Live SpiceDB-binary + Oso-Cloud integration runs are gated; a `spicedb serve` smoke under `@pytest.mark.spicedb` is the one residual live-path follow-on.)
- **Malformed-row audit:** ✅ DONE (P0.5) — durable AuditSink (InMemory + SurrealAuditSink) wired into chunk_source; malformed-row drops are queryable governance records, not just logs.
- **Index-level pre-filter for graph/SQL/lexical modes:** ✅ DONE (P0.6) — all three non-vector modes now DROP unauthorized content at the query (`id IN $allow`), not post-hoc; hardened + mutation-proven per mode. (Wiring these three retrievers into the live `RAGPipeline` mode-router is the integration follow-on, alongside the text-to-SQL + Tracer pipeline-wiring items below.)
- **Wire text-to-SQL agent + GuardedBigQuery into the live pipeline/router** (P0.3b governance advisory): the agent is built standalone (like GuardedBigQuery, the TurboVecRetriever before P0.2c). Integration: route warehouse-SQL queries through `TextToSqlAgent` from `RAGPipeline`; derive the `mask` flag from the real `GovernanceDecision` over the warehouse asset (session-derived, NOT a literal bool); source the `ColumnPolicy` set from the catalog asset (single governance source, not the agent's `masked_columns` kwarg). → integration/P0.6-era work, pairs with the other pipeline-wiring follow-ons.
- **Wire the Tracer into the live pipeline + Langfuse attribute allowlist** (P0.5 follow-on): the `Tracer` is a facade with 0 `.span()` calls in `src/` today. Integration: add spans around route/retrieve/rerank/govern/generate in `RAGPipeline`, AND a **Langfuse span-attribute ALLOWLIST** (only metric keys like cost_usd/tokens/mode/request_id exported) so a careless `span("generate", answer=...)` can never leak chunk content to Langfuse Cloud. -> integration/P0.6-era work.
- **Wire the SemanticCache into the live `RAGPipeline.query`** (P0.7 follow-on): the cache is built+hardened standalone (like the retrievers/Tracer were). Integration: at `query()` entry, when `cfg.cache_enabled`, `cache.get(question, session, govern_fn)` where `govern_fn` re-runs the L5 `SecurityFilter` over the stored chunk ids for the session; on miss, run the pipeline then `cache.put(...)`. Emit `record_cache_hit(...)` on a hit. Choose the backend from `cfg.cache_backend` (memory|surreal). The permission-aware invariant is already enforced by the cache; wiring must pass a govern_fn that is the REAL governance (not identity). → integration/P0.6-era work, pairs with the other pipeline-wiring follow-ons.
- **Cache invalidation on re-embedding/version bump** (P0.7 → P0.9 CDC): `SurrealCacheStore.invalidate_version(stale)` is the hook; wire it to the CDC/re-embed pipeline so a corpus re-embed drops stale cache entries. → P0.9.
- **Broaden view-miner/glossary coverage** (P0.4 finding): the view-miner only mines *aliased view columns*, so the drift-clean claim is scoped to the **mined set** (documented in `test_glossary_drift_clean_against_mined_columns`), not the full physical estate. Broaden coverage (mine query logs / dbt manifests / profile-then-draft every physical column) so drift-clean spans the full `legacy_mart` schema. → P0.4 follow-on.
