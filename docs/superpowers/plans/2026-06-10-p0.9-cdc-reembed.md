## Headline governance invariant (fail-closed — the P0.9 leak oracle)
**A data change must NEVER leave stale authorization reachable.** This phase mutates data UNDER a live governance model, so propagation is the risk. Three sub-invariants, each hardened + mutation-proven:

1. **DELETE / tombstone** — a deleted/source-removed chunk becomes UN-retrievable across ALL modes, dropped from the allowlist, AND evicted from the semantic cache. *Mutation:* skip tombstone propagation → deleted chunk still retrievable → fails.
2. **RECLASSIFICATION (the sharp one)** — a chunk whose `sensitivity_class`/ACL changes (B→F, public→restricted) is IMMEDIATELY governed by the NEW class; an under-cleared session that could see it before is now deny/redact, AND any cache entry computed under the OLD class is invalidated (a stale cache hit can't serve now-restricted content). *Mutation:* skip cache-invalidation-on-reclassify → stale permissive entry served → fails. Treat like the leak oracle.
3. **RE-EMBEDDING preserves SecurityContext** — a version-bump re-embed must NOT drop/alter a chunk's ACL (cls, allowed_roles, need_to_know, clearance). *Test:* re-embed → SecurityContext byte-identical; governance decision unchanged.

**Why the cache is the sharp part:** the allowlist + per-mode retrieval read LIVE from the store `chunk` row, so a reclassify/delete is reflected in governance the moment the row changes. But the semantic cache holds GOVERNED RESULTS computed under the old state — so the propagator MUST evict affected cache entries (by chunk_id for delete/reclassify; by version for re-embed).

## Spine (serial, single-writer) — Tasks 0–3
- **T0 — store delete/tombstone (`store/surreal.py`).** `delete_chunk(chunk_id)` (REMOVE the row + its `links` edges — RecordID-bound, SECURE) so retrieval/allowlist no longer see it. Add a `deleted_ts` tombstone option for audit/replay (soft-delete) but the retrieval-facing guarantee is: gone from `chunk_security_rows` + `get_chunk_row` + all 3 mode queries. SPINE.
- **T1 — cache invalidate-by-chunk-id (`cache/semantic_cache.py` + `cache/surreal_cache.py`).** `invalidate_chunk(chunk_id)` on BOTH stores: drop every entry whose `chunk_ids` contains it (in-mem: scan `_entries`; durable: `DELETE query_cache WHERE $cid IN chunk_ids`). Idempotent. This is the reclassify/delete cache propagation. (`invalidate_version` already exists for re-embed — P0.7.) SPINE.
- **T2 — CDC event model (`cdc/events.py`).** `ChunkChangeEvent` (op: insert|update|delete|reclassify, chunk_id, payload, source_version:int). Monotonic `source_version` for ordering (a stale event with version <= last-applied is a no-op — idempotent + ordered). SPINE.
- **T3 — `CdcProcessor` (`cdc/processor.py`).** Applies events to (store + cache) atomically per event: insert/update → `upsert_chunk` + `invalidate_chunk` (any cached result over the old text is stale); reclassify → `upsert_chunk(new cls/level)` + `invalidate_chunk`; delete → `delete_chunk` + `invalidate_chunk`. **Version-ordered** (per-chunk last-applied version map; stale event dropped). **Idempotent** (replaying an applied event is a no-op). **RESILIENT** (bounded retry budget on a failing event; exhausted → audited drop, not silent). **TRANSPARENT** (each event emits a span + audit `cdc_applied`/`cdc_dropped`). SPINE.

## Workers (parallel, disjoint files) — flag fan-out
- **WORKER-A — DELETE propagation headline (`tests/test_cdc_delete.py`).** Delete a chunk via CDC → never in any mode (graph/structured/lexical) + dropped from allowlist + every cache entry that referenced it is gone. Mutation-documented: skip `delete_chunk` OR skip `invalidate_chunk` → still reachable.
- **WORKER-B — RECLASSIFICATION headline (`tests/test_cdc_reclassify.py`).** The sharp leak oracle: cache a result for an under-cleared session over a class-B chunk → reclassify B→F via CDC → (1) the under-cleared session's NEW retrieval denies it (allowlist re-derived), AND (2) the stale cache entry is invalidated so a re-query is a MISS (not the old permissive hit). Mutation: skip cache-invalidate-on-reclassify → stale permissive entry served → fails.
- **WORKER-C — re-embed preserves SecurityContext + version (`cdc/reembed.py` + `tests/test_reembed.py`).** `ReEmbedder` re-embeds chunks under a new `embedder_version`, preserving cls/level/roles byte-identical; bumps version; calls `cache.invalidate_version(old)`. Resumable + bounded batch. Test: SecurityContext unchanged + governance decision identical + old-version cache misses.
- **WORKER-D — CDC robustness (`tests/test_cdc_processor.py`).** Idempotent replay (apply twice = once); version ordering (stale event dropped, newer wins); bounded retry + audited drop on persistent failure; TRANSPARENT spans/audit per event.
